Triage Nubbix por dentro

Qué le pasa a un ticket de soporte desde que el cliente lo escribe hasta que un agente humano recibe la propuesta. Cada paso dice qué hace en simple, qué palabras técnicas usa, qué puede salir mal con la IA, quién lo controla y cuál es su código real.

Código fijo siempre hace lo mismo; se testea exacto IA decide un modelo; puede variar y equivocarse Datos guarda o lee información

El mapa completo

Las flechas con texto son los desvíos: cada vez que algo no está bien, el ticket sale del camino y va a una persona o termina en un error. Nunca sale algo dudoso al cliente.

flowchart TD
  A["Ticket del cliente"] --> B{"Guardrail de entrada<br/>patrones"}
  B -- "vacío o muy largo" --> E1["Error"]
  B -- "patrón de ataque" --> S1["Respuesta segura<br/>y revisión humana"]
  B -- "ok" --> C{"¿Está en la caché?"}
  C -- "sí" --> OUT["JSON para el agente humano"]
  C -- "no" --> D{"Moderador IA<br/>de entrada"}
  D -- "riesgo o falla" --> S1
  D -- "ok" --> P["Prompt YAML<br/>+ ticket entre etiquetas"]
  P --> L["Modelo LLM<br/>salida estructurada"]
  L --> V{"Validación<br/>del contrato"}
  V -- "inválido: reintento" --> L
  V -- "3 fallos" --> E2["Error"]
  V -- "válido" --> G{"Guardrail de salida<br/>patrones"}
  G -- "promesa o fuga" --> R["Reemplazar el answer"]
  G -- "ok" --> M{"Moderador IA<br/>de salida"}
  M -- "riesgo" --> R
  M -- "ok" --> K["Guardar en caché"]
  R --> K
  K --> OUT

Paso por paso

10 paradas, en el orden en que las recorre triage() en src/service.py. Tocá cada una para abrir la explicación; adentro está el código real, extraído del repositorio.

  1. 1
    Código fijo El ticket entra por la línea de comandos La persona escribe la consulta y elige proveedor, prompt y moderación. Ver explicación y código

    Qué hace, en simple

    El programa recibe el texto del cliente desde la terminal. Todavía no se habló con ninguna IA: solo se leen las opciones y se cargan las claves del archivo .env. Lo que el cliente escribió se trata siempre como texto, nunca como una orden.

    Palabras técnicas

    CLI
    Programa que se usa escribiendo comandos en la terminal, sin pantallas ni botones.
    stdout / stderr
    Dos “salidas” de un programa: por stdout sale el resultado (el JSON); por stderr salen avisos y errores, para no mezclarlos.

    Qué puede salir mal

    Acá no hay IA, así que no hay riesgo de modelo. El riesgo es humano: una clave pegada en el código o subida a GitHub.

    Quién lo controla

    Las claves viven en .env, que .gitignore excluye del repositorio.

  2. 2
    Código fijo Guardrail de entrada: patrones de ataque Busca frases conocidas de manipulación. Si encuentra una, no se llama a la IA. ↳Si encuentra un patrón → respuesta segura + revisión humana (no se llama a la IA) Ver explicación y código

    Qué hace, en simple

    Antes de gastar una llamada, el código revisa el texto con patrones: reglas que reconocen frases típicas de ataque, como “ignorá tus instrucciones” o “modo desarrollador”. Primero pasa todo a minúsculas y sin tildes, para que “Ignorá” e “ignora” se reconozcan igual. Si hay coincidencia, el ticket va directo a una persona.

    Palabras técnicas

    Guardrail
    “Baranda de seguridad”: un control que frena lo peligroso antes o después del modelo.
    Prompt injection
    Cuando alguien escribe instrucciones dentro del ticket para que la IA desobedezca sus reglas.
    Regex (expresión regular)
    Una forma de describir patrones de texto, por ejemplo “una palabra que empieza con ignor seguida de instrucciones”.
    Determinista
    Que con la misma entrada da siempre la misma salida. Lo opuesto a un modelo de IA.

    Qué puede salir mal

    Los patrones solo reconocen frases conocidas. Medido hoy: 7 trucos de escritura pasan sin ser detectados (espacio invisible, letras cirílicas, números por letras, letras separadas, base64, portugués y sinónimos).

    Quién lo controla

    Hay tests sin IA en tests/test_guardrails.py (13). Lo que se escapa lo tiene que frenar la capa siguiente: el moderador.

    Dato medido

    Evals adversariales: los patrones frenaron 6 de 10 ataques, a costo 0 y sin latencia.

  3. 3
    Datos Caché: ¿ya respondimos esto? Si la misma consulta ya se respondió, se devuelve la respuesta guardada. ↳Si ya estaba → devuelve la respuesta guardada Ver explicación y código

    Qué hace, en simple

    Se arma una “huella” del pedido con el proveedor, el modelo, la versión del prompt y la consulta normalizada. Si esa huella ya está guardada, se devuelve la respuesta anterior: costo 0 y casi sin espera.

    Palabras técnicas

    Caché
    Memoria de respuestas ya calculadas, para no repetir el trabajo.
    Hash MD5
    Una función que convierte cualquier texto en un código corto y fijo. Acá sirve de etiqueta, no de seguridad.

    Qué puede salir mal

    La huella no incluye el modo de moderación: una respuesta guardada con la moderación apagada se reutiliza con la moderación prendida. Y una respuesta mala, una vez guardada, se repite.

    Quién lo controla

    Está documentado como limitación en el README. No hay test de la caché (el README lo marca como pendiente).

  4. 4
    IA Moderador IA de entrada Una IA aparte puntúa de 0 a 1 si el ticket intenta manipular. No lo responde. ↳Si hay riesgo o el moderador falla → respuesta segura + revisión humana Ver explicación y código

    Qué hace, en simple

    Otra IA (Haiku) recibe el ticket entre etiquetas y solo lo puntúa en tres riesgos: inyección, jailbreak y extracción. Si algún puntaje llega a 0,5, se bloquea. Si el moderador falla o responde mal, el ticket también se bloquea: ante la duda, decide una persona.

    Palabras técnicas

    LLM
    Modelo de lenguaje: la IA que lee y escribe texto.
    Jailbreak
    Intentar que la IA salga de sus reglas con un personaje, una ficción o una falsa autoridad.
    Fail-closed (falla cerrada)
    Si el control se rompe, el sistema bloquea en vez de dejar pasar.
    Umbral
    El número desde el cual algo cuenta como riesgo. Acá, 0,5.

    Qué puede salir mal

    Es una IA: puede equivocarse en los dos sentidos (dejar pasar un ataque o bloquear un ticket normal). Además el atacante escribe justo lo que el moderador lee.

    Quién lo controla

    El modo de falla cerrada, más el guardrail y el moderador de salida después. Se mide con los evals adversariales.

    Dato medido

    Frenó 3 de los 4 ataques que pasaron los patrones. Haiku: 0,95 s y 0,000072 USD por llamada (264 llamadas).

    Mostrar el código real de este paso
  5. 5
    Código fijo Prompt versionado + ticket entre etiquetas Las instrucciones viven en un YAML; el ticket va encerrado entre <ticket> y </ticket>. Ver explicación y código

    Qué hace, en simple

    Las instrucciones para la IA no están en el código: están en archivos YAML (v1 sin ejemplos y v2 con ejemplos). El texto del cliente se coloca dentro de etiquetas <ticket>, y el prompt dice que eso es un dato, no una orden.

    Palabras técnicas

    Prompt / system prompt
    Las instrucciones que recibe la IA. El “system prompt” fija su rol y sus reglas.
    Zero-shot
    Pedirle la tarea solo con instrucciones, sin ejemplos (v1).
    Few-shot
    Darle algunos ejemplos resueltos para que imite el criterio y el formato (v2).
    YAML
    Un formato de texto simple para guardar configuración.

    Qué puede salir mal

    Las etiquetas ayudan, pero no son una pared: un atacante puede escribir </ticket> para “cerrar” el dato antes de tiempo.

    Quién lo controla

    El patrón etiquetas_falsas del guardrail de entrada bloquea esas etiquetas. Se usa replace y no format, para que las llaves del ticket no rompan la plantilla.

    Dato medido

    v1 y v2 aciertan lo mismo (98%), pero v2 manda unas 2 veces más tokens de entrada (Haiku: 1.868 contra 729 de promedio).

  6. 6
    IA El modelo responde con salida estructurada Se llama al proveedor elegido pidiéndole un JSON con un esquema fijo. Ver explicación y código

    Qué hace, en simple

    Se le manda a la IA el prompt y el ticket, y se le exige responder con una forma exacta: un JSON con answer, confidence, category y actions. El razonamiento interno va apagado o bajo, porque sus tokens se comían el tope y cortaban la respuesta.

    Palabras técnicas

    Proveedor
    La empresa que ofrece el modelo por internet (Anthropic, Groq). Los dos se usan con la misma interfaz.
    Salida estructurada
    Obligar al modelo a responder con un formato fijo (un esquema JSON), en vez de texto libre.
    Token
    Pedacito de texto (más o menos media palabra). Se cobra y se limita por tokens.
    MAX_TOKENS
    El máximo de tokens que puede escribir el modelo en una respuesta. Acá, 500.
    Temperature
    Cuánto varía la respuesta. 0 = lo más estable posible.

    Qué puede salir mal

    La IA puede clasificar mal, inventar, prometer cosas o seguir una orden escondida en el ticket. Antes del arreglo, 17 respuestas salieron cortadas justo en 500 tokens.

    Quién lo controla

    La validación del paso siguiente, los guardrails de salida y los evals (40 casos etiquetados a mano).

    Dato medido

    Haiku v1: 2,03 s y 0,00021 USD por llamada. Groq gpt-oss-120b v1: 1,49 s, gratis. Después del arreglo: 0 respuestas inválidas en 237 llamadas.

  7. 7
    Código fijo Validación del contrato y reintentos Pydantic revisa el JSON; si no cumple, se reintenta hasta 3 veces con el error concreto. ↳Si falla → reintenta (hasta 3). Si falla 3 veces → error Ver explicación y código

    Qué hace, en simple

    Lo que devolvió la IA se revisa contra el contrato: que la categoría sea una de las cuatro, que la confianza esté entre 0 y 1, que haya al menos una acción. Si algo falla, se le vuelve a preguntar al modelo diciéndole exactamente qué estuvo mal. Después de 3 intentos, el servicio devuelve un error en lugar de inventar.

    Palabras técnicas

    Contrato
    La forma acordada de la respuesta. Si no se cumple, la respuesta no sirve.
    Pydantic
    Librería de Python que valida que los datos tengan la forma y los tipos esperados.
    Reintento con feedback
    Volver a pedir, pasando el error, para que el modelo se corrija.

    Qué puede salir mal

    Un JSON válido puede ser igual de incorrecto: la forma está bien, pero la categoría o la respuesta están mal.

    Quién lo controla

    Los evals miden si la categoría es correcta. No hay test de los reintentos sin IA (pendiente en el README).

    Dato medido

    Reintentos en las corridas finales: 0.

  8. 8
    Código fijo Guardrail de salida: promesas y fugas Busca promesas (reintegros, plazos) y pedazos del system prompt en la respuesta. ↳Si encuentra algo → reemplaza el answer Ver explicación y código

    Qué hace, en simple

    Antes de que la respuesta llegue al cliente, el código busca promesas que solo puede hacer una persona (“te vamos a devolver”, “de inmediato”) y frases copiadas de las instrucciones internas: 8 palabras seguidas iguales cuentan como fuga.

    Palabras técnicas

    Fuga de prompt
    Cuando la IA revela sus instrucciones internas.
    Promesa indebida
    Comprometer algo (un reintegro, un plazo) que solo puede decidir un agente humano.

    Qué puede salir mal

    Solo se revisa answer: las actions no pasan por este control (src/service.py, línea 150). Van al agente humano, no al cliente, pero una acción manipulada podría inducirlo a error.

    Quién lo controla

    Tests sin IA: las 40 respuestas reales de Groq no deben marcarse. Si se marca algo, el moderador de salida no hace falta.

    Dato medido

    Ataque adv-07 con Groq v1: el modelo escribió “le confirmaré el estado de la devolución”. Ningún patrón la reconoció; la frenó el moderador de salida (promesa_indebida = 0,60).

    Mostrar el código real de este paso
  9. 9
    IA Moderador IA de salida Si los patrones no vieron nada, una IA busca promesas o fugas dichas con otras palabras. ↳Si marca riesgo → reemplaza el answer Ver explicación y código

    Qué hace, en simple

    Los patrones no entienden paráfrasis. Un moderador IA puntúa la respuesta en tres riesgos: promesa indebida, fuga interna y obediencia a la inyección. Si marca algo, la respuesta se reemplaza por una genérica y el agente recibe la tarea de redactarla.

    Palabras técnicas

    Paráfrasis
    Decir lo mismo con otras palabras. Los patrones fallan ahí; una IA no tanto.
    Falso positivo
    Marcar como peligroso algo que no lo era.

    Qué puede salir mal

    Falsos positivos: en los evals con Groq marcó 5 respuestas, y algunas parecen normales. Ahí el cliente recibe una respuesta genérica en vez de una útil.

    Quién lo controla

    La revisión humana de los casos marcados (el README los analiza uno por uno).

    Dato medido

    Haiku: 1,07 s y 0,000088 USD por llamada (205 llamadas). Con el de entrada, el moderador suma unos 0,00016 USD por ticket: el 74% del costo de generar con v1.

    Mostrar el código real de este paso
  10. 10
    Datos Caché, métricas y JSON final Se guarda la respuesta, cada llamada queda medida y el JSON sale para el agente. Ver explicación y código

    Qué hace, en simple

    La respuesta final se guarda en la caché. Cada llamada a una IA dejó antes una línea en data/metrics.jsonl con tokens, tiempo, costo y si cumplió el contrato. El JSON sale por stdout para el agente humano, que es quien decide.

    Palabras técnicas

    JSONL
    Un archivo de texto con un objeto JSON por línea. Se agrega al final, nunca se borra.
    Métrica
    Un número medido (tiempo, tokens, costo) que permite comparar y decidir con datos.
    Human in the loop
    Una persona revisa y decide. La IA propone; no ejecuta acciones.

    Qué puede salir mal

    Lo que la IA sugiere en actions puede sonar convincente aunque esté mal. El servicio no ejecuta nada, pero una persona apurada podría seguirlo sin pensar.

    Quién lo controla

    El contrato dice explícitamente que las acciones son sugerencias. El costo se recalcula con la fórmula y los tokens de cada línea.

    Dato medido

    Gasto real de todo el desarrollo en Anthropic: 0,112 USD (1.184 llamadas a IA en total).

Cómo vigilar lo que hace la IA

Las ideas que atraviesan todo el proyecto. Sirven para cualquier servicio con IA, esté escrito en Python, TypeScript o lo que sea.

  • Separá lo fijo de lo que decide la IALos pasos de código fijo se testean con certeza. Los pasos de IA se miden con evals: muchos casos y un porcentaje, nunca una sola prueba.
  • Defensa en capasNinguna capa alcanza sola: patrones (baratos, rígidos) + moderador IA (entiende paráfrasis, se equivoca) + revisión humana.
  • Falla cerradaSi un control se rompe, que bloquee. El costo es una respuesta genérica; el beneficio, que no se escape nada.
  • Medí antes de cambiarCada decisión de este proyecto tiene un número detrás: tokens, latencia, costo, aciertos. Sin dato, es opinión.
  • Test exploratorioProbá a mano cosas que nadie anotó: tildes raras, otros idiomas, textos larguísimos, emojis. Así aparecieron los 7 trucos que pasan los patrones.
  • La IA propone, la persona decideEl servicio nunca ejecuta acciones. Si alguna vez lo hiciera, cada acción necesitaría su propio control.

Cómo correrlo

Desde la carpeta del proyecto. Los comandos que usan Anthropic gastan créditos; los tests no llaman a ninguna IA.

Instalar

python -m venv .venv
.venv\Scripts\Activate.ps1      # Windows
pip install -r requirements.txt
cp .env.example .env              # y completar las claves

Clasificar un ticket

python -m src.main "me cobraron dos veces la suscripción"

Elegir proveedor, prompt y moderación

python -m src.main "no puedo entrar" --provider anthropic --prompt v2 --moderation off

Correr los evals (40 casos)

python evals/runner.py --provider groq --prompt v1

Correr los ataques (10)

python evals/adversarial_runner.py --provider groq --prompt v1

Tests sin IA (costo 0)

python tests/test_guardrails.py
